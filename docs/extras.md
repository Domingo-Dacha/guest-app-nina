# Гостевой раздел «Допуслуги»

Раздел `/extras` открывается кнопкой на главной странице и использует существующую
проверку сессии. Экраны каталога, услуги, корзины, оформления, результата и заказов
доступны через параметр `view`. Категория и выбранный заказ находятся в URL;
введённые параметры и положение списка сохраняются при навигации внутри раздела.

## Демонстрационные данные

Контекст — существующее вымышленное проживание из каталога: «Тестовый гость»,
«Дом у сосен», 16–18 октября 2026, 4 гостя. Контакт — `guest@example.test`.
Новые анкета, авторизация и бронирование проживания не создаются.

Цены, состав, дополнения, категории и правила находятся в
`src/data/fixtures/extras.ts`, доступны экранам через репозиторий. Фурако стоит
7 000 ₽ за один день и 8 000 ₽ за два дня; украшение в бочку и сибирская пихта —
по 2 000 ₽; халат — 500 ₽ за штуку. Два дня фурако должны быть до дня выезда.
Дополнения изначально выключены. Завтрак — прежние 1 900 ₽ за набор на двоих,
поздний выезд — 5 000 ₽. Сап — 2 000 ₽, длительность пока не определена и
согласовывается отдельно. Велосипеды бесплатные, наличие требует согласования;
заказ только из бесплатных позиций оформляется без экрана оплаты, со статусом
`not_required`. Фурако, сапы и велосипеды не подтверждаются автоматически.

Фермерская корзина, обед, ужин, бани «Венский», «Гавшино» и «Райская» добавлены
без установленной цены: карточки доступны для просмотра, оформление заблокировано
и на клиенте, и на сервере. Райская баня показывается только гостям «Меридиана»
(в текущем демонстрационном проживании «Дом у сосен» её нет).

Фотографии предоставлены владельцем. Дополнительно подключены новые снимки обеда,
завтрака, халатов и фермерской корзины. Фото бургера используется в карточке
«Ужин» без установленной цены; отдельной карточки «Бургер» нет. В категории
«Еда» четыре карточки: завтрак, обед, ужин и фермерская корзина.
Фото халатов показано рядом с выбором количества.
Для трёх бань временно используется
один снимок по указанию владельца. Путь `/images/extras/` публичен для загрузки
и оптимизации фотографий; страницы и API по-прежнему требуют сессию. Для услуг
без фотографий остаются декоративные заглушки. Пустые категории скрыты.

Завтрак заказывается строго до 18:00 предыдущего дня в `Europe/Moscow`.
Доступность времени ограничена проживанием и серверным текущим временем.
Завтрак подтверждается автоматически по демонстрационным правилам. Фурако и
поздний выезд остаются на согласовании — свободные слоты и работа менеджера
не имитируются. Реального канала сообщений нет.

## Хранение и границы

`/api/extras` проверяет серверную сессию; запись дополнительно требует
`DEMO_WRITES_ENABLED=true`. Идентификаторы команды и проживания определяет сервер,
клиент их не выбирает. Все SQL-запросы ограничены `team_slug` и `stay_id`.
Существующий PIN общий для команды: это демонстрационная изоляция команды и
тестового проживания, а не авторизация отдельных реальных гостей.

Миграция `0002_extras.sql` добавляет четыре таблицы: `extras_carts`,
`extras_cart_items`, `extras_orders`, `extras_order_items`. Состав и цены заказа
сохраняются в отдельных типизированных столбцах. Статусы оплаты и выполнения
разделены; предусмотрены согласование, подтверждение, выполнение, отмена,
ожидающий возврат и возврат. Смена этих статусов сотрудниками не входит в прототип.

Миграция `0003_extras_catalog.sql` расширяет список услуг и добавляет отдельные
типизированные столбцы длительности, пихты, количества халатов и их цен. Старые
заказы сохраняют свои исходные цены; новые поля получают нейтральные значения.
Для бесплатных заказов разрешена нулевая сумма только со статусом `not_required`.
Миграция `0004_extras_burger.sql` добавляет идентификатор бургера в ограничения
списка услуг, сохраняя все существующие данные. Этот исторический идентификатор
сохранён в схеме для совместимости, но удалён из каталога; карточка «Ужин»
использует существующий идентификатор `dinner`. Новая миграция не требуется.

Версия корзины защищает от перезаписи в нескольких вкладках. Изменившиеся цены
требуют явного принятия новой суммы. Сроки и цены проверяются при переходе к
демооплате и при сохранении заказа. Заказ, его позиции и очистка корзины
сохраняются атомарно; повторный ключ или повторная версия корзины возвращают
тот же заказ. Ошибка и отмена демонстрационной оплаты не очищают корзину.
Заказы и корзина читаются с сервера после перезагрузки и на другом устройстве.

## Публикация и проверки

Локальный сервер и локальная подключённая база не нужны. `npm run verify`
проверяет код, правила времени/цен, HTTP-границы и SQL на изолированном PostgreSQL
в памяти (PGlite). Внешнее соединение с базой при этих тестах не используется.
`npm run test:e2e` запускается в GitHub Actions на 390 px WebKit и desktop Chromium.
Браузерные тесты используют детерминированный тестовый API, а реальные SQL,
ограничения, откат и одновременное оформление проверяются отдельно.

Workflow публикации отправляет проверенную версию `main` на удалённую сборку
Vercel. Команда из `vercel.json` после успешной сборки применяет миграции до
публикации. Защищённая переменная `DATABASE_URL` доступна внутри Vercel;
`vercel pull` возвращает для неё заглушку, поэтому в GitHub её не выгружаем.
Миграции разрешены только в Vercel Production с `DEMO_WRITES_ENABLED=true`.
Локальные проверки и Preview базу не изменяют. Секреты не копируются и не
выводятся. Миграция добавляет таблицы, не изменяя старые данные и авторизацию.
PR с миграцией и workflow требует ручной проверки и слияния согласно AGENTS.md.

Для реальных заказов потребуются: контекст и индивидуальная авторизация гостя
из системы бронирования; достоверная доступность, меню и аллергены; согласование
менеджером и канал связи; платёжный провайдер с серверными уведомлениями,
возвратами и юридическими условиями. Сейчас карты не собираются и списаний нет.

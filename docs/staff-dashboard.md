# Кабинет сотрудников — первая демонстрационная версия

Адрес: `/staff`, ссылка «Сотрудникам» в шапке приложения.
Вход через существующий PIN команды, затем выбор демонстрационной роли.
Это общие тестовые роли, а не персональные учётные записи сотрудников.
Не использовать для реальных гостей или финансовых операций.

## Что работает

- Кухня видит питание, баня — бани и фурако, сервис — остальные услуги.
  Управляющий видит все направления и общую сумму заказа.
- По умолчанию «Все даты»: видны и заказы на будущие даты. Также есть «Сегодня»,
  «Завтра» и произвольный диапазон до 31 дня включительно.
  Даты и время московские. Задания сортируются по дате услуги и готовности,
  а не по времени оформления. Дата оплаты не ограничивает появление задания.
- Каждая позиция гостевого заказа — отдельное задание. Завтрак и фурако
  одного заказа связаны номером заказа, но исполняются независимо.
- В работу идут оплаченные позиции с согласованным временем; бесплатные
  допускаются только при нулевой сумме заказа. Возвраты блокируют выполнение.
- Управляющий подтверждает время согласуемых услуг. Кухня отмечает этапы
  «В работе», «Готов к доставке», «Доставлен»; баня — «В работе», «Готово к
  назначенному времени», «Выполнен»; остальные услуги — «В работе», «Выполнен».
- Все изменения сохраняются в PostgreSQL с автором и временем. Страница
  обновляется каждые 15 секунд и при возвращении в окно. Конкурирующие действия
  защищены версией записи. Смена исполнения не меняет оплату или другие позиции.
- Завтрак стоит 900 ₽ за человека; сводка кухни считает порции. Старые
  оплаченные наборы на двоих сохраняют свою цену и две порции на набор. Состав отдельных блюд
  пока отсутствует в гостевом меню, поэтому не придумывается в кабинете.
- Управляющий ведёт реестр ручного переноса: статус, номер бронирования,
  номер/ссылка записи, комментарий, автор и время. Отметка «Перенесён вручную»
  требует оба номера. Журнал изменений реестра также хранится в БД.

## Границы версии

Bnovo и Telegram не подключены. Реестр не создаёт начислений или платежей;
это отметка ручного действия, а не результат сверки внешней системы.
В разделе показываются демооплаты приложения, реального платёжного провайдера
нет. Нет автоматического импорта заказов Bnovo, сверки сумм и кодов услуг,
платёжных идентификаторов, частичных возвратов или уведомлений.
Фермерская корзина оформляется внешним переходом в Telegram, поэтому такие
обращения не появляются в кабинете автоматически.

Для реального запуска нужны персональные серверные учётные записи и назначение
ролей администратором, привязка реальной брони/платежей, согласованный процесс
отмен и проверка API Bnovo на тестовой брони. Переключатель деморолей нужно убрать.

## Данные и доступ

Миграция `0006_staff_dashboard.sql` добавляет состояние и версию исполнения
в `extras_order_items`, журналы `staff_task_events`, `staff_transfer_events`
и реестр `staff_transfer_records`. Существующие заказы не удаляются и не
переоцениваются. Новые задания читаются прямо из строк заказов без дублирования.
Каждый запрос и изменение ограничены `team_slug` и направлением роли.
Контакты и имена гостей в API сотрудников не передаются.

Выбранная демороль хранится в отдельной подписанной HttpOnly cookie на 12 часов;
она не заменяет проверку PIN-сессии. Владелец PIN может выбрать любую демороль —
это намеренное ограничение демонстрации, не защита реальных сотрудников.
Preview сохраняет общий запрет записи без явного включения demo writes.

## Проверки

`npm run verify` — линтер, TypeScript, модульные/SQL/API тесты и production build.
SQL-тесты используют PGlite в памяти со всеми настоящими миграциями, не живую БД.
`npm run test:e2e` в GitHub Actions — Chromium и мобильный WebKit 390 px;
проверяются смена ролей, согласование, этапы, обновление между окнами,
ручной реестр, даты, ошибки и запрет записи в preview.
Браузерные тесты используют API double; серверные ограничения отдельно
проверяются на реальном SQL. Локальный dev-сервер для этой работы не нужен.

## Тариф завтрака с 1 октября 2026

Миграция `0007_breakfast_per_person.sql` добавляет снимок числа порций на единицу
заказа. NULL означает прежний формат: два человека на набор завтрака; новые
заказы записывают 1 явно. Суммы и количество в оплаченных заказах не изменяются.
При пересчёте неоплаченной корзины старые наборы переводятся в количество
человек с сохранением порций и явным подтверждением новой суммы. Прежний максимум
6 наборов на двоих соответствует 12 людям; ограничения других услуг не меняются.
